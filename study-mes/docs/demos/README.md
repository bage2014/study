## 二、Demo 统一模板

每篇必须完整包含下述 6 节，缺节即视为未完成。

### 0. 场景背景

一段话说清：**谁、在什么时点、因为什么被迫发起这单业务、不做的后果**。航天场景必须交代件状态（D/Y/F/B）与影响的 SN 范围。

### 1. 前置状态快照

用表格给出流程起点，读者能对账：

- 相关单据号及其状态字段
- 相关 SN / LOT 的当前状态
- 相关库存行（`inv_lot.qty / alloc_qty / lock_flag`）
- 技术状态基线（生效 Rev、生效日期、更改单号）
- 数量基线（引用主数据文档第五章，不得改数值）

### 2. 逐步推演（核心，每步固定 6 段）

```
### 步骤 N ｜ 动作名
触发：谁 + 什么条件 + 哪个入口（菜单/接口/扫码）
校验：命中哪条拦截规则；不通过时单据停在哪、谁收到什么待办
单据：单号、状态机 from → to、必填字段取值
数据变化：表名 → 行 → 字段 before / after（Markdown 表格；新增行标 [+]，删除行标 [−]）
下游：发布的事件名 + 幂等键 + 各系统落了什么
守恒：引用断言编号（A1…A10）并写出实际数字
```

硬性要求：

1. **每步至少一张表级 diff**。禁止只写"更新工单状态"这种无字段无值的话。
2. 数字必须能加总对上。库存、报工、成本三处最容易漂。
3. 跨系统步骤要写清**时序**（同步调用还是异步事件、失败谁重试）。
4. 关键 SQL 用代码块给出，但不超过 15 行。

### 3. 异常分支

至少 2 条，每条包含：**错误做法 → 系统是否拦得住 → 若拦不住脏数据长什么样 → 如何回滚/红冲**。
航天场景优先写：跳序、代签、资质过期、批次混用、超差未闭环就放行、ECN 中途切换造成 `pos` 重复。

### 4. 对账校验点

给出 3～5 条"跑完这单之后查什么表能确认没跑偏"的具体查询，附期望结果。

### 5. 指标与代价

这单业务让哪些指标动了多少个点，以及金额/工期代价。至少覆盖：齐套率、一次交检合格率、追溯耗时、停工损失工时、SN 归集成本偏差。

## 三、写作约束

| 约束 | 原因 |
|------|------|
| 物料编码、SN、LOT、单据号一律取自 [贯穿样例](./demo-case-sada-20261116.md) | 7 篇要能串成一条链 |
| 不编造标准号；只使用 GJB 9001C、AS9100/AS9102 这类确证通用的 | 避免知识文档失真 |
| 术语统一：技术状态更改（不写"ECN 变更"）、双五条归零、关重件、特殊过程、超差让步、多余物 | 与主数据文档一致 |
| 表名小写下划线，字段 `code` 包裹 | 与 [tech-data-model](../tech/tech-data-model-20260816.md) 一致 |
| 每篇 300～450 行 | 低于 300 行说明数据变化没展开 |
| 结尾"相关文档"至少 3 条交叉引用 | 保持知识库连通 |
