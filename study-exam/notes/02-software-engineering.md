### 1.1 ★ CMM / CMMI 过程成熟度（2024/2025 连考）

> CMMI（能力成熟度模型集成）评价**组织的软件过程能力**，注意是"组织级过程"成熟度，不是项目规模

| 级别 | 名称 | 关键词 |
|------|------|--------|
| 1 | **初始级 Initial** | 混乱、靠英雄、成功不可重复 |
| 2 | **已管理级 Managed** | 项目级过程已建立，有计划/配置/质量保证，能按计划交付 |
| 3 | **已定义级 Defined** | 组织级标准过程，项目可裁剪，过程文档化标准化（**关键跃迁：项目级→组织级**） |
| 4 | **量化管理级 Quantitatively Managed** | 用统计/量化数据（SPC）管理过程，性能可预测 |
| 5 | **持续优化级 Optimizing** | 持续过程改进、缺陷预防、技术革新 |

口诀：**初 管 定 量 优**（1 混乱 → 2 有规矩 → 3 标准化 → 4 可量化 → 5 自优化）
- 跳跃特征：2→3 从"项目有过程"到"组织有标准过程"；4→5 从"量化管理"到"主动持续改进"
- CMMI 两种表示法：**连续式**（能力等级 0-3，评单个过程域）和**阶段式**（成熟度 1-5，评组织整体）
- 过程域 PA：2 级有项目策划、配置管理、质量保证、需求管理等；4 级有量化项目管理、组织过程性能；5 级有因果分析与解决、组织绩效管理

### 1.2 ★ 净室软件工程 Cleanroom（2024/2025 连考）
核心思想（背 3 条）：
1. **形式化方法**：用盒结构（黑盒/状态盒/清晰盒）和数学方法规约、设计、**正确性验证**
2. **以正确性数学验证代替单元测试**：团队评审证明代码正确，开发者不做传统调试
3. **统计测试（基于使用模型的统计质量控制）**：按用户使用概率生成测试用例，认证软件可靠性（MTBF）
- 特点：缺陷预防而非缺陷消除；近乎零缺陷目标；不主张穷举测试
- 名字来源：类比半导体"净室"——从源头防止缺陷进入

### 1.3 其他方法学
- **结构化方法**：自顶向下、逐步求精、模块化（SA/SD/SP），面向数据流
- **面向对象方法**：Booch / OMT / OOSE（Jacobson）→ 统一为 UML
- **Jackson 方法**：面向数据结构，以输入输出数据结构驱动程序结构
- **形式化方法**：基于严格数学定义（Z 语言、VDM、Petri 网），高可靠系统
- 软件复用：代码级 / 设计级 / 分析级 / 测试级复用；复用形式分组装式（构件库组装）与共享式

### 5.3.1 ★ McCabe 环路复杂度（高频计算）
- 衡量程序复杂程度的图论指标，三种等价算法：
  1. **V(g) = E − N + 2**（E 有向边数，N 节点数）
  2. **V(g) = P + 1**（P 判定节点数——出度为 2 的分支节点数）
  3. **V(g) = 闭合区域数 + 1**（控制流图区域数，含图外区域）
- 含义：**独立路径的条数 = 环路复杂度**，即至少需要的测试用例数
- 例：一个 if-else 嵌套 while 的图，E=11、N=9 → V(g)=11−9+2=**4**
- 建议：V(g) ≤ 10，超过则程序难测试维护，应拆分
- 判定节点：if / for / while / case（多分支按 n−1 个判定算）等产生分支的语句

## 8. 软件质量

### 8.1 ISO/IEC 9126 六大特性
- 功能性 / 可靠性 / 易用性 / 效率 / 维护性 / 可移植性

### 8.2 ISO/IEC 25010 八大特性（现行标准，替代 9126）
- **功能适合性 / 性能效率 / 兼容性 / 易用性 / 可靠性 / 信息安全性 / 维护性 / 可移植性**
- 记忆：比 9126 多了"兼容性""信息安全性"独立成项，"功能性"改名"功能适合性"，"效率"改名"性能效率"
- 质量模型分：使用质量模型 + 产品质量模型

### 8.3 McCall 模型
- 产品运行 / 产品修订 / 产品转移 三视角 11 个特性
  - 运行：正确性、可靠性、效率、完整性、易用性
  - 修订：可维护性、灵活性、可测试性
  - 转移：可移植性、可复用性、互操作性

### 8.4 软件度量
- **LOC 代码行**：直观但偏向复杂长代码，不能衡量语言差异
- **FP 功能点**：从用户视角按外部输入/输出/查询、内部逻辑文件、外部接口计数，与语言无关
- 用例点 UCP、对象点；GQM（目标-问题-度量）方法

### 9.3 ★ COCOMO 成本估算模型
- **基本 COCOMO**：E = a_b × (KLOC)^b_b（人月）；D = c_b × E^d_b（月）
- 三类项目：
  - **有机型 Organic**：小团队、熟悉环境、约束少（a=2.4, b=1.05）
  - **半独立型 Semi-detached**：中等复杂度（a=3.0, b=1.12）
  - **嵌入型 Embedded**：强约束、软硬件紧密耦合、实时高可靠（a=3.6, b=1.20）
- **中级 COCOMO**：基本模型 × 15 个成本驱动因子 EAF（产品/硬件/人员/项目四组）
- **详细 COCOMO**：分阶段（原型/设计/集成）再加成本因子
- **COCOMO II**：适配现代开发，三个阶段：应用组装（对象点）、早期设计（功能点）、后体系结构（代码行 + 7 个规模因子 + 17 个成本因子）
- 其他估算：专家判断（Delphi 德尔菲法，多轮匿名收敛）、类比估算、Putnam 动态多变量模型

### 9.4 系统架构师文档产出
- 架构设计文档 SAD：架构视图、质量属性场景、架构决策记录 ADR、接口规约、部署拓扑
- IEEE 1471（现 ISO/IEC/IEEE 42010）：架构描述 = 多个视图，每个视图对应一个视点（viewpoint），干系人关切驱动
- 需求跟踪矩阵 RTM：需求 ↔ 设计 ↔ 代码 ↔ 测试用例双向可追溯
