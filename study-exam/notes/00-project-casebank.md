## 通用项目"金句"（可直接搬到论文）

> 根据实际情况选用，避免假大空。

1. 本项目采用 Spring Cloud Alibaba 全家桶构建微服务体系，网关采用 Spring Cloud Gateway，注册与配置中心采用 Nacos，限流熔断使用 Sentinel，链路追踪采用 SkyWalking。
2. 数据库层面采用"读写分离 + 分库分表 + 多级缓存"三层架构，MySQL 1 主 4 从 + ShardingSphere 水平拆分，Redis 3 主 3 从 Cluster 模式做热点数据缓存。
3. 项目严格遵循 DDD 限界上下文拆分原则，每个服务独立部署、独立数据库，服务间通过 OpenFeign 同步调用与 RocketMQ 异步事件解耦。
4. 部署基于 Kubernetes + Jenkins CI/CD 流水线，采用金丝雀发布策略，支持一键回滚，平均发布时间从 30 分钟降低到 2 分钟。
5. 为保障 99.99% 可用性，系统按 3 副本跨 AZ 部署，配合 Prometheus 监控 + 四级告警体系 + 全链路压测 + 混沌工程演练。

## 使用 Tips

1. 每次准备论文，先从这个案例库复制数据槽位到模板，保证所有模板引用的项目一致
2. 细节越真实越好（具体公司名、具体数据量、具体故障案例）
3. 如果实际项目中没有某项技术，可以合理"叠加"：比如项目没用 K8s，可以说"我主导设计了 K8s 部署方案并试运行 3 个服务"——只要你真的懂能自圆其说
4. 不要虚构你不了解的技术，答辩时（虽然架构师没有答辩）写在论文里的任何技术都要能讲清楚原理
