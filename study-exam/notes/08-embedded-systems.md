# 08 嵌入式系统

> 嵌入式系统基础 + 实时 OS + 任务调度 + AUTOSAR + 可靠性设计
> 占比：上午 3-5 分；**下午案例试题三几乎每年必考（15 分）**
> 真题套路：AUTOSAR 分层填空 / RM-EDF 调度判定 / RTOS 特性填空 / 嵌入式 DB 特点

## 1. 嵌入式系统基础

### 1.1 定义与特点
> 以应用为中心、以计算机技术为基础，软硬件可裁剪，对功能、可靠性、成本、体积、功耗严格要求的专用计算机系统。

六大特点（必背）：
1. **专用性强**：面向特定应用，不像通用 PC
2. **资源受限**：内存小、CPU 算力有限、功耗低
3. **实时性要求**：硬实时场景必须在截止时间内响应
4. **高可靠性**：常年无人值守运行（汽车、医疗、航天）
5. **软硬件协同**：软件固化在 Flash/ROM，软硬件一体化设计
6. **交叉开发**：宿主机（Host，x86 PC）写代码 → 交叉编译 → 下载到目标机（Target）调试

### 1.2 组成
```
硬件层：嵌入式处理器 + 存储器(ROM/Flash/RAM) + I/O + 电源/时钟
   ↓
中间层：BSP（板级支持包 = Bootloader + 硬件驱动 + HAL）
   ↓
系统软件层：嵌入式 OS（RTOS）+ 文件系统 + 网络协议栈 + GUI
   ↓
应用软件层：具体业务（如发动机控制、胎压监测）
```

### 1.3 嵌入式处理器分类
| 类型 | 特点 | 典型 | 场景 |
|------|------|------|------|
| MCU 微控制器 | 单芯片集成 CPU+存储+外设 | 8051、STM32（Cortex-M） | 家电、工控终端 |
| MPU 微处理器 | 需外配存储/外设，算力强 | ARM Cortex-A、i.MX | 手机、网关、车机 |
| DSP 数字信号处理器 | 哈佛结构、硬件乘加、流水线深 | TI C2000/C6000 | 雷达、音频、电机控制 |
| SoC 片上系统 | CPU+GPU+DSP+加速器集成 | 麒麟、骁龙、特斯拉 FSD | 手机、智驾域控 |

### 1.4 冯·诺依曼 vs 哈佛结构（必考辨析）
| 维度 | 冯·诺依曼 | 哈佛 |
|------|-----------|------|
| 存储 | 指令数据共用同一存储器/总线 | 指令、数据分用两个存储器/两条总线 |
| 取指 | 取指和取数不能同时 | 可同时取指+取数，并行度高 |
| 代表 | x86 PC、ARM（修正哈佛） | 8051、DSP、多数 MCU |
| 适用 | 通用计算 | 嵌入式、实时信号处理 |

> ARM Cortex 系列多为"修正哈佛结构"（L1 分 I-Cache/D-Cache，L2 合一）。

### 1.5 ARM 处理器系列
- **Cortex-A**（Application）：跑 Linux/Android，高端，如 A53/A72/A76
- **Cortex-R**（Real-time）：硬实时，汽车制动、硬盘控制器
- **Cortex-M**（Microcontroller）：MCU 内核，低功耗，M0/M3/M4/M7
- ARM 版本：ARMv7（32 位）→ ARMv8/ARMv9（64 位，AArch64）

## 2. BSP 板级支持包（高频填空）

> BSP = 介于硬件与 OS 之间的一层软件，针对具体板子定制

包含：
1. **Bootloader**：上电后第一段程序，初始化硬件、引导 OS（U-Boot、RedBoot）
2. **硬件相关驱动**：串口、网口、Flash、定时器
3. **硬件抽象层 HAL**：屏蔽硬件差异，向上提供统一接口

常考点：BSP 与 OS 关系——**同一 OS 跑在不同板子上，只需更换 BSP**；BSP 是硬件与操作系统之间的桥梁。

## 3. 嵌入式操作系统

### 3.1 常见嵌入式 OS
| OS | 特点 | 场景 |
|----|------|------|
| VxWorks | 硬实时、确定性最强、风河公司 | 火星探测器、波音、军工 |
| QNX | 微内核、POSIX、安全认证 | 汽车数字座舱、医疗 |
| FreeRTOS | 开源、轻量（内核几 KB）、抢占式 | IoT、STM32 |
| μC/OS-II/III | 开源、可裁剪、实时 | 教学、工控 |
| 嵌入式 Linux | 开源、生态好、实时性一般（可打 PREEMPT_RT 补丁） | 网关、车机、路由器 |
| Android | Linux 内核 + 应用框架 | 手机、车机 |
| HarmonyOS | 微内核、分布式软总线 | IoT、手机、汽车 |

### 3.2 RTOS 实时操作系统特征（必背）
1. **多任务/抢占式调度**：高优先级任务可随时抢占低优先级
2. **任务有优先级**：静态或动态
3. **中断处理快、中断延迟短且确定**
4. **内核可裁剪、可重入**
5. **支持任务间同步与通信**：信号量、互斥量、消息队列
6. **确定性**：关键操作（上下文切换、中断响应）时间有上界

### 3.3 硬实时 vs 软实时
| 类型 | 截止时间错过后果 | 例子 |
|------|------------------|------|
| 硬实时 | 灾难性，绝对不允许超时 | 安全气囊、ABS 刹车、火箭制导、心脏起搏器 |
| 软实时 | 服务质量下降，可容忍偶尔超时 | 视频点播、直播、12306 查票 |

### 3.4 实时性三大指标
- **中断延迟**：中断发生 → 进入 ISR 第一条指令的时间（越短越确定越好）
- **任务响应时间**：事件发生 → 任务开始执行
- **吞吐量**：单位时间处理的事件数

## 4. ★ 任务调度算法（案例计算题高频）

### 4.1 基本概念
- 任务三元组：**(C, T, D)** = 执行时间 C、周期 T、截止时间 D（常令 D=T）
- CPU 利用率：U = C / T（单任务）；多任务 U = Σ(Cᵢ/Tᵢ)
- 调度方式：抢占式 / 非抢占式

### 4.2 ★ RM 速率单调调度（Rate Monotonic）
- **静态优先级**：任务上线前分配好，不再变化
- 规则：**周期越短，优先级越高**（速率 = 1/周期，速率大优先）
- 可调度判定（Liu-Layland 界限）：

```
U = Σ(Cᵢ/Tᵢ) ≤ n × (2^(1/n) − 1)
```

| 任务数 n | 1 | 2 | 3 | 5 | 10 | ∞ |
|----------|---|---|---|---|----|----|
| 界限值 | 1.0 | 0.828 | 0.780 | 0.743 | 0.718 | ln2 ≈ **0.693** |

- 判定口诀：算总利用率 → 和 n×(2^(1/n)−1) 比 → 小于则一定可调度；大于不代表一定不行（界限是充分非必要）

### 4.3 ★ EDF 最早截止时间优先（Earliest Deadline First）
- **动态优先级**：运行时按"谁的截止时间最早谁先跑"实时分配
- 可调度判定：**U ≤ 1（100%）** 即可调度，比 RM 利用率上限高
- 缺点：动态调度开销大、实现复杂、过载时行为不可预测

### 4.4 其他调度
- **时间片轮转 RR**：同优先级轮流
- **FCFS**：先来先服务，非抢占
- 实际 RTOS：**基于优先级的抢占式调度 + 同优先级时间片轮转**（如 FreeRTOS、μC/OS）

### 4.5 RM vs EDF 对比（案例常考表）
| 维度 | RM | EDF |
|------|----|----|
| 优先级 | 静态固定 | 动态变化 |
| 依据 | 周期短者优先 | 截止时间近者优先 |
| 可调度上限 | 0.693（n 大时） | 1.0 |
| 开销 | 小 | 较大 |
| 可预测性 | 好 | 过载时差 |
| 工业应用 | 多（简单可靠） | 少 |

### 4.6 计算题示例
> 3 个周期任务：T1(C=1, T=4)、T2(C=2, T=6)、T3(C=1, T=8)
> U = 1/4 + 2/6 + 1/8 = 0.25+0.333+0.125 = **0.708**
> RM 界限 n=3：3×(2^(1/3)−1) ≈ 0.780 → 0.708 ≤ 0.780，**RM 可调度**
> EDF：0.708 ≤ 1，**EDF 可调度**

## 5. ★ 优先级反转（高频案例题）

> 现象：低优先级任务持有锁，中优先级任务长期占用 CPU，导致**高优先级任务被中优先级间接阻塞**。

经典案例：1997 火星探路者号（Pathfinder）系统复位。

解决两招：
| 方法 | 规则 |
|------|------|
| **优先级继承 Priority Inheritance** | 低任务持锁期间，临时继承等待该锁的最高任务优先级，用完恢复 |
| **优先级天花板 Priority Ceiling** | 锁一被持有，持有者直接升到所有可能用该锁任务中的最高优先级（天花板），提前防死锁 |

区别：继承是"被高优先级等了才升"（被动）；天花板是"一拿锁就升到顶"（主动、更激进）。

## 6. 任务状态与同步通信

### 6.1 任务四态
就绪 Ready → 运行 Running → 阻塞 Blocked（等事件/延时）→ 挂起 Suspended；运行结束 → 删除

### 6.2 同步与通信机制
| 机制 | 用途 |
|------|------|
| 信号量 Semaphore | 同步（二值）+ 资源计数（计数） |
| 互斥量 Mutex | 临界区互斥，**支持优先级继承** |
| 消息队列 Message Queue | 任务间异步传数据，有缓冲 |
| 共享内存 | 最快，但需配互斥访问 |
| 信号 Signal | 异步通知（类软中断） |
| 事件标志组 Event Flags | 多事件"与/或"等待 |
| 管道/邮箱 | 字节流 / 单条消息传递 |

### 6.3 中断相关
- 上半部分（顶半部）：ISR 只做紧急事（清中断、标记），越快越好
- 下半部分（底半部）：耗时处理延后（tasklet/工作队列/软中断）
- ISR 中**不能**调用会阻塞的 API（如等信号量）

## 7. ★ AUTOSAR 汽车软件架构（近年案例连续考）

> AUTomotive Open System ARchitecture，汽车电子开放式系统架构
> 目标：汽车 ECU 软件标准化、可复用、可交换，解耦应用软件与硬件

### 7.1 三层架构（必背，填空考）
```
┌─────────────────────────────────────┐
│  应用层 Application Layer            │  SWC 应用软件组件
│    SWC1  SWC2  SWC3 ...              │
├─────────────────────────────────────┤
│  RTE 运行时环境（Virtual Functional  │  通信中间件，SWC 之间/
│  Bus 虚拟功能总线 VFB 的实现）        │  SWC 与 BSW 唯一接口
├─────────────────────────────────────┤
│  基础软件层 BSW（Basic Software）     │
│   ① 服务层 Services                  │  OS/通信/存储/诊断/网络管理
│   ② ECU 抽象层 ECU Abstraction       │  对外设统一访问（I/O/存储/通信）
│   ③ 微控制器抽象层 MCAL              │  直接操作寄存器，最贴近硬件
└─────────────────────────────────────┘
```

记忆要点：
- **RTE 是核心**：SWC 只能通过 RTE 通信，不直接接触 BSW/硬件 → 实现软件与硬件解耦
- BSW 自上而下：**服务层 → ECU 抽象层 → MCAL**
- SWC 端口通过 RTE 的 PPort/RPort 通信（Sender-Receiver / Client-Server 两类）
- Classic（CP，传统 ECU）与 Adaptive（AP，自动驾驶域控，跑 POSIX、SOA 通信）两个平台

### 7.2 嵌入式数据库（案例考过特点填空）
常用：**SQLite**（零配置、单文件、库级锁）、Berkeley DB（KV、嵌入式键值）、Empress、eXtremeDB

特点（与企业 DB 对比，背 5 条）：
1. 体积小、可裁剪，与应用同进程运行（通常无独立 Server 进程）
2. 内存占用低，部分为内存数据库
3. 高可靠性，支持事务、崩溃恢复
4. 实时性：确定性响应，部分支持优先级调度
5. 支持 Flash 等嵌入式存储，SQL 可能精简（部分只支持 KV 接口）

## 8. 嵌入式系统设计与开发

### 8.1 开发模式
- **宿主机-目标机交叉开发**：Host 编辑/编译 → 交叉编译器（如 arm-linux-gcc）→ 下载 Target
- 调试：JTAG/SWD 仿真器、在线仿真器 ICE、gdbserver 远程调试
- 流程：需求 → 规格说明 → 软硬件划分（协同设计）→ 软硬件并行开发 → 集成 → 固化测试

### 8.2 软硬件协同设计
- 软硬件功能划分：性能/功耗敏感且固定的用硬件（FPGA/ASIC），灵活多变的用软件
- 统一描述语言：SystemC、UML/SysML

### 8.3 嵌入式中间件
- 汽车：AUTOSAR RTE、SOME/IP（面向服务的车载以太网通信）、DDS
- IoT：MQTT、CoAP、LwM2M、IoT 网关协议适配

## 9. 可靠性与低功耗设计

### 9.1 可靠性手段
| 手段 | 说明 |
|------|------|
| 看门狗 WDT | 定时器，程序必须定期"喂狗"；跑飞未喂狗 → 硬件复位（硬狗优于软狗） |
| 双看门狗 | 主备互相监控 |
| 掉电保护 | 检测低压 → 中断保存现场到 EEPROM/FRAM |
| 冗余 | 双核锁步（Dual-Core Lockstep，汽车功能安全）、三模冗余 TMR 表决 |
| 信息冗余 | ECC 内存、CRC、海明码 |
| 软件容错 | N 版本编程、恢复块、数据一致性检查、断言 |
| 功能安全标准 | IEC 61508（通用）、ISO 26262（汽车 ASIL A-D）、DO-178C（航空） |

### 9.2 低功耗设计
- **DPM 动态功耗管理**：空闲时切休眠/关机模式，唤醒源触发
- **DVFS 动态电压频率调节**：负载低时降频降压（功耗 ∝ C·V²·f，降压收益平方级）
- 硬件：低功耗芯片、时钟门控、电源门控
- 常用指标：MIPS/W（能效比）

### 9.3 多核操作系统模式
| 模式 | 说明 |
|------|------|
| AMP 非对称多处理 | 各核跑独立 OS/任务，分工固定 |
| SMP 对称多处理 | 一个 OS 管所有核，任务可迁移 |
| BMP 绑定多处理 | SMP 但任务可绑定到指定核（实时性折中） |

## 10. 案例答题模板

### 题型 A：AUTOSAR 分层补全
- 看到"SWC 通信""统一接口"→ 填 **RTE**
- 看到"操作寄存器""最底层驱动"→ 填 **MCAL**
- 看到"外设统一访问、不关心具体芯片"→ 填 **ECU 抽象层**
- 看到"OS、诊断、网络管理"→ 填 **服务层**

### 题型 B：调度判定
1. 算每个任务利用率 C/T
2. 求和 U
3. 题问 RM：与 n(2^(1/n)−1) 比（n 大时直接用 0.693）
4. 题问 EDF：与 1 比
5. 比较 RM/EDF：静态/动态、周期/截止时间、0.693/1、开销

### 题型 C：RTOS/嵌入式特点简答
- 实时性：抢占式 + 中断延迟短且确定
- 可靠：看门狗、掉电保护、ECC
- 资源受限：可裁剪、小内核
- 同步：信号量/互斥量/消息队列；优先级继承解决反转
