### 二、质量属性概述（200 字）

ISO/IEC 9126 将质量属性分为 6 大特性（功能性、可靠性、易用性、效率、维护性、可移植性）。架构设计关注的核心质量属性可归为 6 类：性能、可用性、安全性、易用性（运行期）与可修改性、可测试性（开发期）。每个质量属性都通过"质量属性场景六要素"（刺激源、刺激、制品、环境、响应、响应度量）具体化为可验证的场景。架构评估方法 ATAM（架构权衡分析方法）正是基于场景进行多属性权衡的工程化方法。

2. 性能场景示例（六要素展开）：
   - 刺激源：正常用户 + 大促秒杀
   - 刺激：5 万 TPS 请求下单
   - 制品：订单服务 + 交易链路
   - 环境：峰值（大促前 1h）、部分节点故障
   - 响应：正常处理、限流降级非核心请求
   - 响应度量：平均响应 < 100ms、P99 < 200ms、成功率 > 99.9%
3. 可用性场景示例（六要素）：
   - 刺激源：机房网络故障 / 某节点 OOM / DB 主从切换
   - 刺激：单节点不可用 / 单 AZ 故障
   - 制品：交易全链路
   - 环境：正常运行 7×24
   - 响应：自动摘除故障节点、流量切正常节点、用户无感
   - 响应度量：RTO < 30s、RPO = 0、年停机 < 53 分钟（99.99%）
4. 优先级排序（效用树）：
   - P0（必须）：可用性（故障自动转移）、性能（峰值响应）、安全性（交易防重）
   - P1（重要）：可修改性（需求 1 周上线）、可测试性（核心链路自动化覆盖率 80%）
   - P2（可选）：易用性（控制台）

### 四、核心质量属性的战术设计（500 字）

{分论点 2：}
1. 性能战术：
   - 资源需求侧：减少事件处理层数（合并中间件）、提升计算效率（算法优化 + JVM 调优）、减少传输数据量（Protobuf 替代 JSON）
   - 资源管理侧：多级缓存（本地+Caffeine + 分布式+Redis）、异步并发（RocketMQ 削峰）、线程池隔离（Hystrix/Sentinel 舱壁模式）
   - 资源仲裁侧：优先级队列（核心交易高优）、静态资源 CDN
2. 可用性战术：
   - 故障检测：心跳（Nacos 3s 未响应剔除）、Ping/Echo、异常监控（Prometheus + Alertmanager）
   - 故障恢复：冗余（3 副本 + 跨 AZ）、重启（K8s livenessProbe 自动拉起）、选举（DB MHA / Redis Sentinel）、回滚（版本化发布 + 一键回退）
   - 故障预防：移除故障节点（摘除 5min）、进程监控（Sentinel 熔断）、事务回滚（Seata AT 模式）
3. 安全性战术：
   - 身份认证（JWT + 刷新令牌）、授权（RBAC + 数据权限）
   - 机密性（传输 TLS 1.3、落盘 AES-256、敏感字段脱敏）
   - 完整性（签名校验、防重放 nonce + timestamp）
   - 审计（全链路操作日志，不可篡改）
