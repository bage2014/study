### 一、项目背景（300 字）

### 二、Web 高并发架构概述（200 字）

Web 系统从单体演进到分布式，高并发设计的核心是"分而治之"：流量分层接入、数据分层缓存、数据水平拆分。业界成熟的做法包括 DNS 轮询、反向代理负载均衡、CDN 静态加速、本地+分布式多级缓存、数据库读写分离与分库分表、消息中间件削峰填谷等。下面结合本项目具体阐述三个核心设计。

### 三、多级负载均衡架构设计（500 字）

{分论点 1：}
1. 为什么需要多级 LB？（单级瓶颈 + 高可用）
2. 具体方案：
   - 第一层：DNS 轮询 + 智能 DNS（按地域解析）
   - 第二层：LVS（DR 模式）四层负载，做流量入口
   - 第三层：Nginx 七层负载，按 URL/Header 路由、静态资源分离
   - 健康检查：Nginx 主动探测 + 剔除异常节点
3. 选型理由：LVS 抗高吞吐、Nginx 灵活路由，两层组合兼顾性能与可用性
4. 项目中的实际效果：抗住了 XX 万 QPS 的流量洪峰

### 四、多级缓存体系设计（500 字）

{分论点 2：}
1. 缓存优先级：CDN → 反向代理（Nginx proxy_cache）→ 应用本地缓存（Caffeine）→ 分布式缓存（Redis Cluster）→ DB
2. 缓存一致性策略：
   - Cache-Aside Pattern（旁路缓存）：先更 DB 再删缓存
   - 热点 Key：本地缓存 30s + 异步刷新
   - 缓存穿透：布隆过滤器
   - 缓存击穿：互斥锁 + 永不过期
   - 缓存雪崩：过期时间随机打散（±5min）
3. Redis 架构：3 主 3 从 Cluster 模式，单 key < 10KB，禁用复杂命令
4. 缓存命中率：上线后 Redis 命中率 97%+，本地缓存命中率 60%+

### 五、数据库读写分离与分库分表（500 字）

{分论点 3：}
1. 读写分离：1 主 4 从，主写从读；通过 MyCat/ShardingSphere 做路由；延迟容忍 < 1s 的走从库，实时性要求高的走主库
2. 分库分表策略：
   - 垂直拆分：订单库 / 用户库 / 商品库 分离
   - 水平拆分：订单表按 user_id 哈希拆 32 库 × 32 表
   - 分片键选择：用户中心按 user_id，订单按 order_id 雪花算法
3. 全局唯一 ID：雪花算法（Snowflake），workerId 按机房 + 实例分配
4. 跨库 join：应用层聚合 + 冗余字段 + 宽表（ES）
5. 效果：单表从 3 亿降到 < 1000 万，查询从 2s 降到 50ms

### 六、总结与反思（200 字）

本项目通过 {三级 LB + 多级缓存 + 读写分离分库分表} 的组合拳，{量化效果}。但在实际运行中也遇到了一些问题：{例如大促期间某热点商品穿透缓存、跨库事务一致性、分库后报表查询困难等}。针对这些问题，后续计划采用 {本地互斥锁 + 最终一致性 RocketMQ 事务消息 + ES 宽表 + 数仓 ODS 层} 等方案优化。未来还将引入服务网格、全链路压测平台等手段，持续提升系统的高并发处理能力。
