## 1. 测试概述

本报告对当前会话中加载的全部技能进行测试用例设计与验证。每个技能对应一条测试用例，
包含触发条件、前置条件、测试 prompt、预期行为与断言清单。
无需外部依赖的技能已在本会话中实测；依赖飞书授权、代码 diff、运行中服务等外部条件的技能，
已设计完整用例并标注前置条件，可通过 `tests/run_skill_tests.sh` 脚本复测。

## 2. 测试方法

1. 扫描技能安装目录，盘点全部技能并按分类（TRAE / common / personal / other / lark）归档。
2. 为每个技能生成测试用例文件 `tests/cases/<skill>.test.md`，包含：技能描述、触发条件、前置条件、测试 prompt、预期行为、断言清单。
3. 对可离线验证的技能，在本会话中直接调用并按断言核对结果。
4. 对需外部条件的技能，标记 `requires_external=yes` 并在报告中列出复测步骤。
5. 使用 `tests/verify_skills.py` 统一管理用例、记录结果、生成汇总。

### 5.1 实测记录

#### TC-common-coding — common-coding  **[pass]**

- **触发**: user needs to write code
- **测试 prompt**: `Write a Java method to reverse a string, following best practices and include a brief explanation.`
- **结果与说明**: Produced Java StringUtils.reverse() using StringBuilder.reverse(), null/empty-safe, with private constructor on utility class and explanation. All assertions met.

#### TC-common-project-standard — common-project-standard  **[pass]**

- **触发**: need project structure / conventions / standards
- **测试 prompt**: `Recommend project structure and .gitignore for a Java Spring Boot + Vue monorepo.`
- **结果与说明**: Returned Spring Boot+Vue monorepo directory layout (backend/ frontend/ shared/) and a combined .gitignore (target/, node_modules/, .idea/, *.log, etc.). All assertions met.

#### TC-dynamic-ui — dynamic-ui  **[pass]**

- **触发**: a compact visual makes the answer clearer
- **测试 prompt**: `Show a small bar chart of sales: Jan=10, Feb=20, Mar=15.`
- **结果与说明**: Rendered inline SVG bar chart via PureShowWidget: Jan=10, Feb=20 (focal 'highest'), Mar=15; light+dark token themes; value labels. All assertions met.

#### TC-personal-brief-style — personal-brief-style  **[pass]**

- **触发**: need to enforce brief/caveman response style
- **测试 prompt**: `Answer briefly: what is TDD?`
- **结果与说明**: Actual answer: 'TDD: 测试先行。红-绿-重构。先写失败测试，再写实现，再重构。' — short, direct, no filler words. All assertions met.

#### TC-personal-doc-manager — personal-doc-manager  **[pass]**

- **触发**: manage change logs / spec docs / test reports in docs/
- **测试 prompt**: `Where should I store a spec doc for the 'order' module dated today, and what filename?`
- **结果与说明**: Answered: store under docs/spec/ with filename order-<content>-2026-10-18.md, following {module}-{content}-{date}.md. All assertions met.

#### TC-personal-solution-research — personal-solution-research  **[pass]**

- **触发**: need solution comparison / research
- **测试 prompt**: `Research 3-5 solutions for session storage in a distributed system, comparing functionality/performance/cost/complexity.`
- **结果与说明**: Loaded and provided a >=3-solution comparison framework with dimensions functionality/performance/cost/complexity and industry references. All assertions met.

## 7. 复测方法

测试用例与脚本已保存，可随时重新验证：

```bash
# 列出全部技能及状态
./tests/run_skill_tests.sh list

# 查看某技能的测试 prompt 与断言
./tests/run_skill_tests.sh show common-coding

# 打印某技能的测试 prompt（发给 assistant 执行）
./tests/run_skill_tests.sh run common-coding

# 遍历所有未测用例，依次打印 prompt
./tests/run_skill_tests.sh run-all

# 记录结果
./tests/run_skill_tests.sh record common-coding pass "生成了 null-safe 代码"
./tests/run_skill_tests.sh record lark-im fail "未授权"

# 查看汇总报告
./tests/run_skill_tests.sh report

# 重新生成全部测试用例（基于 tools/generate_skill_tests.py 中的技能清单）
./tests/run_skill_tests.sh regen
```
